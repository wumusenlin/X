# 子项目最近修改快照自动同步设计

## 目标

子项目完成本地提交或远端推送后，自动将该提交同步到 `docs/agent/recent-project-changes.md`，避免协作快照落后于实际 Git 历史。

## 已选方案

在 X 根 `AGENTS.md` 写入强制收口规则：代理对任一 `repos/*` 子项目完成 `git commit` 或 `git push` 时，必须在结束回复前刷新最近修改快照，并将快照作为 X 根仓库独立改动提交。快照只记录已提交的子项目 Git 信息。

本次同时将小控 `2026-07` 分支的 `386d36d` 同步到快照。

## 方案比较

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| 工作区规则强制刷新 | 采用 | 覆盖代理执行的提交与推送，零依赖，和子项目独立 Git 边界一致。 |
| Git Hook 自动改写快照 | 不采用 | Hook 会在各子仓制造隐式副作用，也无法自然完成 X 根仓库提交。 |
| 定时脚本刷新所有项目 | 不采用 | 会产生无关快照提交，不能保证与一次具体子项目变更对应。 |

## 数据与流程

1. 提交或推送后，读取目标子项目的当前分支、工作区状态和 `git log -10`。
2. 更新快照时间、项目状态表及该项目最近十条提交。
3. 只要快照发生变化，在 X 根仓库单独提交该文档；不把子项目嵌套进 X 根仓库提交。
4. 无快照变化时，不创建空提交。

## 约束

- 不修改任何子项目代码、分支或历史。
- 不新增 Hook、脚本或依赖。
- 不自动推送 X 根仓库；是否推送仍由用户单独授权。
- 快照是协作索引，不替代子项目 Git 历史。

## 验收

- `AGENTS.md` 明确规定子项目提交或推送后的快照刷新和 X 根独立提交责任。
- 小控条目包含 `386d36d`，并保留最新十条提交的顺序。
- X 根 `git diff --check` 通过。
